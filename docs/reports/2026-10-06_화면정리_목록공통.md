## 43번 검토 — 화면 문구를 운영자(최고관리자) 눈높이로
화면 문구를 훑어보니 개발 용어가 약 100군데(설명·마우스 설명 75, 영문 코드값 15, 디버그 표시 10).
많은 곳: 단말 상세(드로어) > 단말 설정 > 통신 주기 설정 > 등록·승인 > 원격 제어 > 그룹 스케줄 변경.

제안(A안, 권장): **지우기 / 바꾸기 / "자세히"로 접기** 세 가지 규칙으로 한 번에 정리, 약 2일.
1. 지우기: 사양서 번호(§·ADR·문제점 N번), API 주소(/api/…), 설정 파일 이름(.env·KAKAO_…), 개발 단계(N차), 쓰지 않는 자리표시 부품.
2. 말 바꾸기: Telemetry → 보고, REGISTER_ACK → 승인 정보 전달, CONFIG_SET·SETTINGS_SET → 설정 보내기, ti/ka → 보고 주기/접속 유지 주기,
   브로커 → 단말 통신 서버, LOCAL/EXPIRED/ACTIVE 등 영문 → 한국어(현장 조작·만료·운영).
3. 숫자 대신 결과: cv·sh·ss·crc 같은 비교 숫자는 "단말과 같음/다름" 배지로, 숫자는 "자세히"를 펼칠 때만.
4. "자세히"(접힘, 최고관리자만): 보낸 원문(JSON)·주소(topic)·명령 번호·지문 숫자 — 문제 생겼을 때 단말측과 맞춰 볼 근거로 남긴다.
5. 위쪽 표시: HMAC 알약 → 서버 상태 화면으로만, "Telemetry 유실" → "보고 저장 실패 N건", 대시보드 카드 아래 MQTT·DB·버퍼 줄 삭제.

B안: 위 1~3 + 사람마다 "기술 정보 보기" 스위치(기본 끔). 개발자 정보를 화면 곳곳에 그대로 두고 켜야 보이게 — A안보다 +1일, 화면 코드가 두 갈래가 되어 유지가 번거로움.
→ A안 권장. 정해 주시면 화면별 목록대로 진행.
