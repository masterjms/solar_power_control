### 21번 — 계정 2차안(최고관리자 / 지역관리자 / 게스트)
**구조에 동의한다.** 1차 검토의 가장 큰 걸림돌(업체끼리 같은 동에 섞임)이 사라진다 — 지역은 서로 겹치지 않으므로 그룹 명령(동 단위 주소)을 그대로 쓸 수 있다.

반영할 때 이렇게 하겠다(다르면 알려 주세요):
1. **지역 권한 = 트리 최상위(시·도) 하나 이상.** "경기도 + 인천광역시"처럼 여러 개를 줄 수 있게 만든다(한 개만 가능하게 만들면 나중에 고쳐야 한다). 기본은 한 개.
2. **지역관리자가 보는 것** = 대시보드·알람·단말 목록·지도·그룹 제어·지역·단말 설정·그룹 스케줄 변경 전부 자기 시·도 안 단말만(서버가 거른다 — 화면만 숨기는 것이 아님). "전체" 명령은 지역관리자에게는 자기 시·도 전체.
3. **단말 등록·승인**: 제안대로 UUID 뒤 6자리 검색. 정확히 1대면 승인 창, 2대 이상이면 "N대가 같습니다 — 8자리로 다시 검색" 안내(선택 불가). 승인할 때 자기 시·도 안의 동을 골라야 한다(지금도 동 필수).
4. **지역(법정동)**: 자기 시·도 아래에 동 추가만. 시·도 추가·이름 바꾸기·삭제는 최고관리자.
5. **스케줄 양식**: 양식은 공용(누구나 보고 쓸 수 있음), 수정·삭제는 만든 사람과 최고관리자만. 지정·보내기는 자기 지역만. (지역마다 따로 두면 같은 양식을 여러 번 만들게 된다.)
6. **통신 주기 설정·서버 설정·시스템**: 지역관리자·게스트에게는 메뉴 자체를 숨긴다.
7. **게스트**: 대시보드만. 지도 확대·이동·핀 말풍선은 되고, 단말 목록 행 클릭(LED 제어)·"알람 화면"·"등록·승인 화면" 링크·상세 버튼은 없다.
8. **만기**: 7·15·30·90·180일·1년·무한. 만료되면 로그인 거부(세션도 끊김), 계정 목록에 "만료" 표시, 만료 7일 전부터 최고관리자 대시보드에 안내. 자동 삭제는 하지 않는다(연장·삭제는 최고관리자).
9. **계정 저장**: DB(이미 있는 `admin_user` 표 확장: 역할·지역 목록·만료일·만든 사람·마지막 로그인). 비밀번호는 해시. 최고관리자 첫 계정은 지금처럼 `.env`에서 만들고, 그 뒤 최고관리자는 화면에서 계정을 만든다. **최고관리자를 2명까지** 둘 수 있게 권한다(한 명이 자리를 비우면 아무것도 못 한다). 비밀번호는 8자 이상, 본인 변경 + 최고관리자 재설정.
10. **기록**: 누가 무엇을 했는지(명령·설정·승인·로그인)는 이미 사용자명으로 남는다. 로그인 성공·실패 기록을 추가한다.
11. **삭제·폐기 권한**: 단말 삭제는 최고관리자만, 폐기·중지·거절은 지역관리자도 가능(자기 지역).
12. **작업량**: 약 2주 — 계정 관리 화면·API 3일, 모든 API·화면의 지역 거르기 5일, 6자리 검색·게스트 화면 1일, 시나리오·시험 2일. 배포 때 DB 변경 1회, 단말 영향 없음.

확인 부탁: ① 지역관리자에게 시·도를 여러 개 줄 수 있게(1) ② 최고관리자 2명(9) ③ 양식 공용(5) ④ 게스트 행 클릭 없음(7) ⑤ 삭제는 최고관리자만(11) ⑥ 비밀번호 8자 이상.

### 27번 — DB 보관 기준
**지금 상태**: Telemetry 원문 13개월(월 단위 삭제), 이벤트 1년, 닫힌 알람 1년. 명령·응답, 설정 변경 이력, 스케줄 보낸 기록은 **삭제 규칙이 없다**(계속 쌓임).

**크기 어림**(로컬 실측 Telemetry 1행 약 470B + 색인 ≈ 650B): 단말 1대 = 하루 144건 ≈ 95 KB → **1만 대 = 하루 약 0.9 GB, 한 달 약 28 GB, 13개월 약 360 GB.** 지금 EC2 디스크로는 안 된다. 나머지 표는 다 합쳐도 그 1/20 이하다.

**원칙 제안**: 원문은 짧게, 하루 단위 요약은 영구, 누적은 숫자 한 칸으로.

| Telemetry 원문(10분마다) | **3개월** | 1~13개월 | 일 집계 |

### 29번 — 대시보드 "발전과 사용" 그래프 · "에너지 합계"
**자료**: 23번으로 단말이 보낸 일일 값이 날짜별로 남는다(`telemetry_daily.gen_wh/use_wh`). 그래프는 이 표로, 오늘은 지금 `eg`·`eu` 합으로 그린다. 10/1 이전 날은 서버 추정값(pp 적분)뿐이라 **연한 색 + "추정"** 으로 구분한다.

**제안**:
- 그래프: 날마다 발전(노랑)·사용(파랑) 막대 2개, 오늘은 오른쪽 끝·연하게(진행 중). 기간 **7일(기본) / 30일 / 12개월(월 합계)**. 막대에 마우스를 올리면 값. 단위 kWh↔MWh 자동.
- 범위: 전체(기본) 또는 트리에서 고른 지역(21번 지역관리자는 자기 지역이 기본).
- 에너지 합계(4칸): **금일 발전 · 금일 사용**(지금 `eg`·`eu` 합) · **누적 발전 · 누적 감축**(누적 = 일 집계 합 + 오늘, 감축 = 누적 발전 × 배출계수). 아래에 "반영 n/N대 · 미반영 = 오늘 보고 없음 m대, MPPT 무응답 k대"를 적는다(0 으로 섞지 않음).
- 배출계수(지금 .env 0.4781)를 **서버 설정** 항목으로 옮겨 화면에서 바꾸게 한다. 바꾸면 누적 감축이 다시 계산된다(발전량만 저장하므로).
- 누적 시작 = 서버가 기록을 시작한 날. 폐기된 단말의 과거분도 지역 합계에 남긴다.

### 30번 — 대시보드 "최근 이벤트"
**있는 것**: 단말 이벤트(접속·두절·재부팅·승인·중지·폐기·CONFIG·설정), 알람 발생·해제, 원격 명령과 결과, 그룹 스케줄 보낸 기록, 서버 설정 변경, 로그인.

**제안**: 대시보드 맨 아래 "최근 활동" 카드(전체 폭), 최근 30건, 10초 갱신, 줄마다 시각·종류 색·단말(시설명)·한 줄 설명, 누르면 관련 화면(단말 상세·알람·보낸 기록).
- 넣는 것: 알람 발생/해제, 승인·중지·복귀·거절·폐기, 원격 명령 보냄·끝남(명령 1건에 1줄 — 단말마다가 아님), 그룹 스케줄 보내기 시작·끝, 현장 조작 시작, 재부팅, 서버 설정 변경, 로그인 실패.
- 빼는 것: 10분마다 오는 Telemetry, CONFIG/SETTINGS 내부 응답, 재발송, 로그인 성공(관리 기록에만).
- 접속·두절은 **알람 기준**(ti×3)으로만 — 브로커의 순간 끊김·재접속까지 넣으면 1만 대에서 화면이 그것으로만 찬다. 같은 단말의 같은 종류는 10분 안에 묶는다.
- 필터 칩: 전체 / 알람 / 단말 / 조작 / 관리. 21번 지역관리자는 자기 지역만.
- 구현: 새 표 없이 기존 표를 합쳐 조회(`GET /api/activity?limit=30&kinds=`). 작업량 1.5일.

확인 부탁: 넣는 것·빼는 것 목록이 맞는지, 명령은 1건당 1줄로 괜찮은지.

### 31번 — 대시보드 "시스템" 메뉴
**무엇인가**: 단말이 아니라 **서버 자체의 상태** 점검 화면이다(3차 때 개발 점검용으로 만듦). 지금은 타일 8개 — MQTT 브로커 연결, DB, 브로커 로그 추적, 활성 HMAC 키, 수신 버퍼 대기, 등록 큐, Telemetry 유실, 공용 시험 계정 열림 — 와 `/health`·`/api/metrics` 원문 JSON.

**제안**: 없애지 말고 **"서버 상태"**로 이름을 바꿔 최고관리자에게만 보인다(지역관리자·게스트 숨김). 내용을 운영자 말로 바꾼다:
- 브로커: 1883·8883 연결, 브로커 기준 접속 단말 수
- DB: 정상 여부, 용량(GB), 디스크 여유 %(27번), 마지막 일 집계·보관 삭제 실행 시각
- 처리: 수신 대기 건수, 유실 건수(0 이어야 정상), 명령 진행 중 수
- 보안: 활성 키, 공용 시험 계정(운영 전 닫아야 함), 최근 로그인 실패 수
- 서버: 버전(커밋)·배포 시각·가동 시간
- 원문 JSON 은 "자세히"로 접는다.
작업량 1일. 장애가 났을 때 "단말 문제인지 서버 문제인지"를 가르는 화면이라 운영에 필요하다.
