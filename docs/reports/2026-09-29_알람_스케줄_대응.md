## 돌리면서 고친 것

- **DB 장애 중 `/health` 가 매달림(S2-12 시간 초과).** Postgres 를 멈추면 연결 시도가 약 19초씩 매달려 풀(20)을 채웠고,
  새 배경 작업(알람 재조정·배포 틱)이 더해지자 `/health` 의 `SELECT 1` 까지 풀을 기다렸다. → 연결 5초·풀 대기 10초로 빨리 포기
  (`db.py`), `/health` DB 확인은 2초에서 끊고 `db_ok=false`. 이후 S2-12 는 126초 → 80초, 장애 중 `/health` 15/15 응답.
- 시뮬레이터가 현장 조작 시작 Telemetry 를 원격이 있을 때만 보냈다 → F/W -8 대로 `md` 가 바뀌면 항상(단위 시험 기대값도 고침).
- S7-01: 앞당김 전에 다른 Telemetry 가 `er` 를 싣고 가면 앞당김을 취소하는 것이 펌웨어 규칙 — 시나리오는 "er 가 실린 Telemetry" 를 본다
  (앞당김 경로 자체는 단위 시험).
- 시나리오 정리가 알람·배포 행을 지우지 않아 `--keep-rows` 재실행 뒤 S7-03 이 옛 행을 봤다 → 정리 대상에 추가, 판정은 이번 실행의 행만.
