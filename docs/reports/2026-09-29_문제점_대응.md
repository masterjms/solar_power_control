## 판단한 것

- **#12 밝기의 뜻(단말측 확인 필요).** 사양서 §3.10.7 에서 원격 `pwm` 은 "설치 기준 밝기에 **곱하는** %"다. 설정의 `manual_40w`(설치 기준 밝기)가 70 이고 LED 제어에서 70% 로 보내면 단말 출력은 70 × 70% = 49% 가 된다. 요청대로 "마지막으로 안 값"을 처음 값으로 띄웠지만, 그 값을 그대로 보내면 밝기가 바뀐다. LED 제어의 밝기를 **곱하는 비율**로 둘지 **실제 출력 %**로 둘지 단말측과 정해야 한다.
- **#13 소등 색.** 낮에는 거의 모든 단말이 소등이라 소등 색이 지도를 덮는다. 경고색(노랑·빨강)이면 이상처럼, 회색 계열이면 오프라인처럼 보여서 **색은 녹색(=붙어 있음) 그대로, 속을 비운 원**으로 했다. 점등 판정은 화면의 주등·입간판 표시와 같게 `pw` 앞 두 채널만 본다(3번 채널이 켜져 있으면 지도만 "점등"이 되던 것 확인·수정).
- **#14 180초.** 온라인 단말은 보통 수 초 안에 답한다. `exp` 30초를 넘겨 도착한 명령은 단말이 `EXPIRED` 로 버리므로 3분 넘게 기다려 얻는 것이 적다. 대신 "단말이 보낸 직후 자동 재시도"도 이 3분 안에서만 돈다(단말 주기 `ti` 10분보다 짧다). 늦게라도 받게 하려면 `.env` 로 늘린다. 오프라인 판정은 브로커 로그라, 막 끊긴 단말(keepalive ×1.5 = 7.5분 전)은 온라인으로 보여 보낸 대상에 들어가고 `NO_RESPONSE` 로 끝난다.
- **운영 `.env`**: 배포 블록(docs/04 §8)에 `COMMAND_TIMEOUT_SEC=900` 이 적혀 있었다. 코드 기본값만 바꾸면 운영은 그대로 900이므로 EC2 `.env` 도 180 으로 고친다(배포 명령에 포함).

## 시트 회신

- **12**: [9/29 서버] 원인은 LED 제어 밝기 처음 값이 70/40 으로 고정돼 있던 것. 이제 창을 열면 채널마다 서버가 마지막으로 안 밝기(단말 설정 동기화 값 또는 켜져 있을 때 받은 Telemetry pw 중 최근 것)를 불러오고, 출처·시각을 아래에 적는다. 확인 부탁: 사양서 §3.10.7 에서 원격 pwm 은 "설치 기준 밝기에 곱하는 %"라, 설치 기준 70 에 70% 를 보내면 실제 49% 가 된다. LED 제어 밝기를 "곱하는 비율"로 둘지 "실제 출력 %"로 둘지 정해 주시면 맞추겠다.
- **13**: [9/29 서버] 핀 = 색은 통신, 속은 조명. 오프라인 회색 / 온라인+점등 녹색(찬 원) / 온라인+소등 녹색 테두리(빈 원) / 승인 대기 파랑. 소등을 다른 색으로 하지 않은 이유: 낮엔 거의 전부 소등이라 그 색이 지도를 덮고, 노랑·빨강이면 이상처럼, 회색 계열이면 오프라인처럼 보임. 핀에 마우스를 올리면 "시설명 / 배터리 전압"(오프라인이면 마지막 값 표시). 배포 후 실제 지도에서 확인 부탁.
- **14**: [9/29 서버] 1) 명령을 보낼 때 오프라인인 단말은 보내지 않고 기다리지도 않음(결과에 "오프라인 — 안 보냄"). 대상이 전부 오프라인이면 보내지 않고 알림. 2) 지금까지는 무응답을 15분(900초) 기다렸음 → 3분(180초)으로 줄이고, 3분 안에 응답이 없으면 "무응답(실패)"로 끝냄(그 안에서는 단말이 보낸 직후 자동 재시도 최대 3회). 늦게 ACK 가 오면 그 결과로 바뀜. 시간은 서버 설정으로 조정 가능.
