## 2. 이번에 만든 것 — Docker 납품 묶음
- `scripts/package-release.sh <버전>` → `dist/iotlight-<버전>.tar.gz` 한 파일(이미지 전부 + 실행 구성 + 스크립트 + 가이드). 시험 빌드 366 MB, 약 30초.
- `scripts/install-offline.sh` — 묶음을 푼 폴더에서: 이미지 불러오기 → 버전 맞춤 → 기동(빌드·내려받기 없음) → backend 준비 대기 → 점검. 처음엔 `.env` 를 만들고 멈춘다. 업데이트는 같은 폴더에 새 묶음을 덮어 풀고 같은 명령.
- `infra/scripts/setup-server.sh` — Ubuntu 서버 준비(Docker·시간대·방화벽·swap), 어느 클라우드나 같다.
- compose 의 backend·web 이미지 이름을 버전 붙은 이름으로(`iotlight-backend:${APP_VERSION}`) — 지금 운영(git 방식)은 `local` 로 그대로.
- `docs/08_설치_인계_가이드.md` — 준비물·설치·업데이트·AWS 대응표·망분리 대안·단말과 맞출 것.
- **로컬 시험**: 묶음 생성 → 빌드한 이미지 삭제 → 다른 폴더에서 묶음만으로 설치 → 컨테이너 5개 기동, DB 구조 최신(0011), 서버 상태 ok, 화면 200. 다시 실행(업데이트 경로)도 정상.

## 3. 납품 방식 의견 — 제안하신 방식에 동의
**"기관이 국내 CSAP 클라우드를 직접 계약 → 우리가 그 위에 프로그램 설치·인계 → SW 유지보수 계약"** 이 지금 회사 규모에 가장 맞다.
| 방식 | 우리 부담 | 비고 |
|---|---|---|
| 우리가 운영하는 SaaS | CSAP 인증(우리 몫), 24시간 운영 | 부담 가장 큼 |
| 하드웨어 납품(온프레미스) | 서버 구매·설치·고장 대응 | 기관 전산실 필요 |
| **기관 클라우드에 설치형** | 설치·인계·유지보수 | 클라우드 계약·CSAP 는 기관 몫 |

이 방식에서 챙길 것:
1. **유지보수 접속** — 기관 클라우드에 원격으로 들어가려면 기관 규정(접속 승인·VPN·접속 기록)을 따른다. 업데이트는 묶음 파일 전달 + 기관 담당자 실행도 가능(인터넷 불필요).
2. **기관마다 한 벌** — 기관마다 도메인·인증서·단말 키(HMAC)가 다르다. 단말이 설치 현장에서 **접속 주소·CA 파일을 바꿀 수 있어야** 한다(단말측 확인 필요).
3. **인증서** — Let's Encrypt 는 80 포트가 인터넷에 열려 있어야 자동 갱신된다. 안 되면 기관 인증서 → 단말 CA 파일 교체(51번).
4. **망분리** — 관제 PC 가 인터넷 차단망이면 카카오 지도·Slack 대체 개발(docs/08 §6).
5. **버전 관리** — 기관이 여럿이면 묶음 버전(1.0.0, 1.1.0 …)과 변경 이력을 붙여 어느 기관이 어느 버전인지 관리.
6. **보안 요건** — 51번 보완(비밀번호 규칙·잠금·자동 로그아웃·감사 기록·보안 진단)은 납품 전에 필요.
