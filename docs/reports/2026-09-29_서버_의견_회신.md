# 서버 업무(2026-09-29) — 서버 의견 회신

`서버_업무_2026-09-29.md` §5 "서버 의견을 받고 싶은 것" 답과 구현 상태. 구현 근거: ADR-009(알람), ADR-010(스케줄 배포).

## 1. 알람 기준 시간·등급

추천안(§16.6.2)을 그대로 쓰고, 한 곳만 바꿨다. 기준 시간은 전부 서버 `.env` 로 바꿀 수 있다.

| 항목 | 추천 | 서버 | 이유 |
|---|---|---|---|
| 통신 두절 | 브로커 끊김 또는 `ti × 2 + 5분` 무수신 | 브로커 끊김 또는 **`ti × 3`** 무수신 | 목록·지도·명령 대상의 "온라인" 판정이 이미 `ti × 3` 이다. 알람만 다른 기준이면 "목록은 온라인인데 알람은 두절"이 생긴다. 기본 `ti` 600초면 30분(추천은 25분) |
| CONFIG 불일치 | 30분 | 30분 | 같음 |
| 현장 조작 | `md:1` 1시간 | 1시간 | 같음 |
| 재부팅 잦음 | 하루 3회 | 오늘(KST) 3회 | 날이 바뀌면 자동 해제 |
| 등급 | 경고·주의·정보 | 추천 표 그대로 | — |

- 발생 시각은 조건이 실제로 시작된 때로 적는다(통신 두절 = 끊긴 시각, 승인 대기 = 처음 접속한 시각).
- 판정은 서버가 30초마다 "지금 상태"로 다시 맞춘다. 단말이 `er` 를 2초 앞당겨 보내므로 화면 반영은 1분 안이다.
- `er` 0x0008·0x0040 은 알람을 만들지 않는다. 과보고는 단말의 10분 5건 제한을 그대로 믿는다.

## 2. 스케줄 프로필에 운전 15개를 넣는 것

**추천안대로 넣었다.** 조건만 배포하고 15개를 단말별 화면에서 따로 다루면, 같은 지역에 같은 다단계 밝기를 줄 때
단말 수만큼 손이 간다. 대신 **단말별 10개(기준 밝기 3·fade·배터리 6)는 프로필에 없고, 배포 때 그 단말의 마지막 읽은 값을
그대로 보낸다.** 서버가 값을 모르거나 현장에서 바뀌었을 수 있으면(`ss` 변화) 배포 전에 `SETTINGS_GET` 을 먼저 보낸다.

## 3. 배포 재시도(30초·3회)와 오프라인 자동 배포

추천안대로 했다. 재발송은 S-23 설정 요청과 같은 방식이다(30초 무응답 → 새 `seq`, 3회면 "응답 없음",
단말이 뭔가 보낸 직후면 30초를 기다리지 않고 바로). 오프라인 단말은 "대기"로 두고 다시 접속하면(REGISTER·Telemetry)
자동으로 보낸다. 새로 시작하는 배포는 초당 10대 이하. 화면에 "응답 없는 단말만 다시"(항목당 3번까지)와 취소가 있다.

참고: **원격 명령(COMMAND)은 반대로 오프라인 단말에 보내지 않는다**(문제점 14번 — 지금의 조작이라 늦게 적용되면
혼란). 스케줄은 결국 맞춰야 하는 상태라 기다렸다가 보낸다.

## 4. SCHEDULE_UPDATE 없애고 SETTINGS_SET 으로 통일

**문제없다. 찬성.** 서버는 S-23 에서 이미 `SETTINGS_SET` + `tbl` 을 보내고 있어 새 메시지가 필요 없었다.
crc 는 받은 `suntable.py` 를 고치지 않고 그대로 쓰고, 서울 `69C1DF86`·기본값 지문 `38AF0DBD` 를 단위 시험에 고정했다.
`region` 은 앞뒤 공백·BOM 을 지우고 47B 를 검사한 뒤 보낸다.

## 5. [필수] 규격 중 구현이 어려운 것

없다. 확인 부탁 두 가지:

1. **LED 제어 밝기의 뜻**(문제점 12번 회신과 같은 질문): 원격 `pwm` 은 "설치 기준 밝기에 곱하는 %"라, 설치 기준 70 에
   70% 를 보내면 실제 49% 가 된다. 화면의 밝기를 "곱하는 비율"로 둘지 "실제 출력 %"로 둘지 정해 주면 맞추겠다.
2. **통신 두절 기준을 `ti × 3` 으로 둔 것**(위 1번)이 괜찮은지.

## 시험 (W-3 포함)

- 로컬 시뮬레이터로 알람 4개(S7-01~04)·배포 2개(S7-05~06) 시나리오를 만들어 통과했다.
- **가상 단말(vdev) 시험 환영한다.** 날짜를 알려 주면 서버 쪽을 켜 두겠다.
  서버에 있는 `FFFF00000000000000000001`(PENDING)은 승인하지 않고 둔다.
- **W-3(8883 흐름 재통과)**: 운영 8883 에서 승인 흐름(PENDING → ACTIVE → SUSPENDED → ACTIVE, 거절, 폐기)·CONFIG·원격
  명령을 한 번 더. 날짜를 정해 주면 서버 담당이 화면을 조작하고 결과를 표로 남기겠다(docs/04 §6.5 체크리스트).
