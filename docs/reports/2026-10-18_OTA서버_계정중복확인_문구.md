# 2026-10-18 — OTA 서버 1차 · 계정 아이디 중복 확인 · 보관 기간 문구 (문제점 56·57·58번)

## 56번 OTA 서버 (사양서 §24, 단말측 결론 10/17-3 반영)
| 항목 | 반영 |
|---|---|
| 메뉴 | "그룹 스케줄 변경" 아래 **OTA 관리**(최고관리자) |
| 파일 | `SolarLTE.bin` 올리면 서버가 base64 한 줄 pkg·SHA-256(pkg 기준)을 만든다. 160KB 초과·bin 아님 거부, 같은 파일 중복 거부. DB 저장(백업·설치 묶음에 포함) |
| 주소 | `OTA_BASE_URL/ota/<항목 번호>/<UUID>/<무작위 22자>` 약 73자. 단말·명령마다 다름, 처음 보낸 때부터 2시간, 그 안에서 Range 반복 허용, 끝난 항목·틀린 주소는 거부. 영문·숫자·`/ - _ .` 만, `\/` 이스케이프 없음 |
| 명령 | `OTA_START {job_id, pkg_version 1, url, size, sha256, chunk 3840}` 개별 topic. job_id = 항목 번호 |
| 대상 | 단말 하나 / 법정동(말단) 하나. 시·구 일괄 막음. 운영 단말만, 이미 OTA 중인 단말은 자동 제외 |
| 진행 | 동시 10대·10~16시(서버 설정). 한 대의 끝 = DONE·ROLLBACK·오류 OTA_ACK. 오프라인은 대기 → 접속하면 시작 |
| 시간 | START 30초 × 3회 → 응답 없음. START 뒤 1시간 30분 결과 없음 → 응답 없음(현장 확인). 늦게 온 결과는 결과로 바꿈 |
| 알람 | 받는 중(START 뒤) 단말은 통신 두절 알람을 올리지 않음 |
| 성공 | `DONE`. 펌웨어 전·후(REGISTER fw)도 기록(버전 비교는 버전 관리 시작 뒤) |
| 기록 | 보낸 기록(작업)·단말별 결과·보낸 횟수·받은 조각 수, 단말 이력 OTA_START/OTA_ACK(주소의 무작위 칸은 가림) |
| 그 밖 | "실패·응답 없음만 다시", "대기 취소"(받는 중은 멈출 수 없음), 성공한 적 없는 파일을 법정동에 보낼 때 "1대 먼저" 확인 |

### 로컬 확인 (가짜 단말 2대 — MQTT 접속·OTA_START 수신·Range 다운로드·결과 응답)
| 시험 | 결과 |
|---|---|
| 펌웨어 138,576 B 올림 | pkg 184,768 자(사양서 §24.8 실기 값과 같음), 같은 파일 409, JSON 파일 422 |
| 시·구(안양시 만안구)로 보내기 | 422 "법정동(말단) 하나씩" |
| 19시대(시간대 밖) 법정동 보내기 | 2대 모두 대기로 남음 |
| 시간대 하루 종일 + 동시 1대 | 1대째 DONE 을 받은 뒤에야 2대째 시작 |
| 다운로드 | 49조각, 모두 206·Content-Range 일치, SHA-256 일치 |
| 결과 | 1대 DONE(1.4.0 → 1.4.1), 1대 HASH |
| 틀린 무작위 칸·다른 UUID / 끝난 항목 / 관리 API 로그인 없이 | 404 / 410 / 401 |
| START 를 안 보내는 단말 | 30초마다 다시(3회) → 응답 없음 |
| START 뒤 연락 끊긴 단말 | 받는 중, 오프라인인데 통신 두절 알람 안 열림 |
| 같은 단말 중복 보내기 | 409 / 법정동이면 그 단말만 빼고 만듦 |
| 대기 취소, 늦은 ROLLBACK, 같은 결과 두 번 | 대기만 취소 / ROLLBACK 으로 바뀜 / 이력 1건 |
| 화면 | 1600px 배치, 트리·파일·보내기·보낸 기록·단말별 결과 확인 |

운영 확인 필요: 실제 단말(모뎀 HTTPS·인증서 검증 없음)로 1대 → 법정동 순서. 운영 `.env` 는 바꿀 것 없음(`OTA_BASE_URL` 기본 https://enerz.co.kr).

## 57번 계정 만들기
- 아이디 칸 오른쪽 **중복 확인** 버튼(`GET /api/accounts/check`) — "쓸 수 있는 아이디입니다"(초록) / "이미 있는 아이디입니다"(빨강). 대소문자만 다른 아이디도 같은 것으로 본다.
- 오류 문구: 칸 아래 한국어만, 아래쪽은 "빨간 글씨로 표시한 칸을 고쳐 주세요." — `[422] ACCOUNT_INVALID … {"fields":…}` 가 더 안 나온다(계정 바꾸기 창도 같음).
- 입력칸 높이: 두 칸 모두 "제목 → 입력 → 안내/오류" 순서로 맞춤. 오류가 나도 아이디·비밀번호 칸 위치가 같다(로컬 측정 374px / 374px).
