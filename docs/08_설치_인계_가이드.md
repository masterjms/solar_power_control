# 08. 설치·인계 가이드 — 어느 클라우드·기관 서버에나 (문제점 53번, 2026-10-15)

대상: 기관(지자체)이 계약한 국내 클라우드(KT·NHN·네이버 등 CSAP 인증) 또는 온프레미스 서버에 **우리가 프로그램을 설치해 인계**하는 경우.
지금 운영(AWS EC2)과 **같은 프로그램·같은 구성**이다 — 클라우드 전용 기능을 쓰지 않으므로 고칠 코드는 없다.

## 1. 무엇이 어디에 필요한가

| 구분 | 내용 |
|---|---|
| 서버 | Ubuntu 22.04/24.04 LTS 1대. 시험·소규모: 2 vCPU·4 GB·SSD 50 GB. 1만 대: 8 vCPU·32 GB·SSD 1~2 TB(docs/reports/2026-10-12 검토 3.1) |
| 프로그램 | Docker Engine + compose 플러그인(설치 스크립트 있음) |
| 네트워크 | 고정 공인 IP, 도메인 1개(A 레코드 → 서버 IP) |
| 방화벽(클라우드 콘솔) | 8883 TCP(단말, 전체) · 443/80 TCP(관리 화면·인증서, 전체 또는 기관망) · 22 TCP(관리자 IP 만) · 1883 닫기(시험 때만 접속원 IP) |
| 인증서 | Let's Encrypt 자동(80 이 인터넷에서 열려 있어야 함) 또는 기관 인증서 — **단말 CA 파일과 맞아야 한다(4.3)** |

## 2. 납품 묶음 만들기 (우리 PC, 인터넷 됨)

```bash
cd /c/Users/mstot/solar_power_control && bash scripts/package-release.sh 1.0.0
```
→ `dist/iotlight-1.0.0.tar.gz`(+ `.sha256`). 안에 Docker 이미지 전부(backend·web·브로커·DB·인증서 도구·자동 재시작), 실행 구성, 스크립트, 이 가이드가 들어 있다.
소스 코드·`.env`·인증서·비밀번호는 들어가지 않는다. 기관 서버는 **인터넷 없이** 이것 하나로 설치된다(GitHub·Docker Hub 불필요).

## 3. 설치 (기관 서버)

1. 서버 준비(처음 한 번, Docker 설치 — 인터넷 또는 기관 내부 저장소 필요):
   `sudo bash setup-server.sh` (묶음의 `infra/scripts/setup-server.sh`. Docker 가 이미 있으면 그 단계는 건너뛴다)
2. 묶음을 서버로 올리고 확인·풀기:
```bash
sha256sum -c iotlight-1.0.0.tar.gz.sha256 && sudo tar -xzf iotlight-1.0.0.tar.gz -C /opt && sudo mv /opt/iotlight-1.0.0 /opt/solar_power_control && sudo chown -R $USER /opt/solar_power_control
```
3. 첫 실행 — `.env` 를 만들고 멈춘다:
```bash
cd /opt/solar_power_control && bash scripts/install-offline.sh
```
4. `.env` 채우기(`nano .env`): 관리자 계정·비밀번호, DB·MQTT 비밀번호, 단말 HMAC 키, 도메인, (지도 쓰면) 카카오 키, (알림 쓰면) Slack 주소. 견본의 `change-me-*` 는 전부 바꾼다. `COMPOSE_PROFILES=local-db`(DB 를 이 서버에).
5. 다시 실행 → 이미지 불러오기·기동·점검:
```bash
cd /opt/solar_power_control && bash scripts/install-offline.sh
```
6. 인증서·HTTPS·8883: docs/04 §6.2·§6.2A·§6.2B(도메인만 기관 것으로).
7. 백업·인증서 갱신 cron: docs/04 §6.6·§9.
8. 보안 기본 항목(docs/09): `.env ADMIN_ALLOW_IPS` 로 관리자 PC 대역만 허용, 서버 설정 → 보안 → 자동 로그아웃 30분 이하 확인. (AWS 비용 보고 `cost-report.sh` 는 넣지 않는다 — AWS 전용)

## 4. 업데이트 (유지보수)

새 묶음을 받아 **쓰던 폴더 위에 덮어 풀고** 같은 스크립트를 돌린다. `.env`·`infra/certs`·DB 는 그대로 남는다. DB 구조 변경은 backend 가 뜰 때 스스로 한다.
```bash
sha256sum -c iotlight-1.1.0.tar.gz.sha256 && tar -xzf iotlight-1.1.0.tar.gz --strip-components=1 -C /opt/solar_power_control && cd /opt/solar_power_control && bash scripts/install-offline.sh
```
되돌리기: 이전 묶음을 같은 방법으로 다시 설치(DB 구조가 바뀐 버전이면 백업에서 복구 — docs/04 §9).

## 5. AWS 와 다른 점 — 바꿔 끼울 것

| 지금(AWS) | 다른 클라우드·기관 | 비고 |
|---|---|---|
| EC2 | 그 클라우드의 가상 서버 | 같은 Ubuntu + Docker |
| 탄력적 IP(EIP) | 고정 공인 IP | 단말이 도메인으로 붙으므로 IP 가 바뀌면 DNS 만 |
| Security Group | 클라우드 방화벽·ACL | 1장 표의 포트 |
| EBS 스냅샷(DLM) | 그 클라우드의 디스크 스냅샷/백업 상품 | `pg_dump` 일일 백업(docs/04 §9)은 어디서나 그대로 |
| SSM(브라우저 접속) | SSH(관리자 IP 만) 또는 그 클라우드 콘솔 접속 | 기관 원격 접속 규정(VPN·승인) 따름 |
| Cost Explorer 비용 보고 | 그 클라우드 콘솔의 비용 화면 | `cost-report.sh` 안 씀 |
| CloudWatch 자동 복구 | 그 클라우드의 자동 복구/HA 옵션 | 컨테이너 자동 재시작(autoheal)은 어디서나 그대로 |

## 6. 인터넷이 막힌 망이면 (기관 업무망·망분리)

프로그램 자체는 인터넷 없이 돈다. 막히면 동작이 바뀌는 외부 서비스:

| 외부 서비스 | 막히면 | 대안 |
|---|---|---|
| Let's Encrypt | 인증서 자동 발급·갱신 안 됨 | 기관 인증서 — 단말 CA 파일 교체 필요(단말측) |
| 카카오 지도·주소 검색 | 지도·주소 검색 안 됨(나머지 정상) | 공공 지도(브이월드 등) — 개발 필요 |
| Slack 알림 | 알림 안 감 | 기관 메일·문자 — 개발 필요 |
| UptimeRobot | 밖에서 보는 다운 감시 없음 | 기관 관제·클라우드 상태 점검 |
| GitHub·Docker Hub | 영향 없음(납품 묶음은 인터넷 불필요) | — |

## 7. 단말과 맞출 것 (기관마다)
- 단말 접속 주소(도메인)·포트 8883·CA 파일 — 기관마다 도메인이 다르면 **단말 설정에서 주소를 바꿀 수 있어야** 한다(단말측 확인).
- 단말 HMAC 키는 기관마다 새로 만든다(`.env`) — 단말 계정 비밀번호가 기관마다 달라진다.
