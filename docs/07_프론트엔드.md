# 07. 프론트엔드 (관리 화면)

- 작성일: 2026-09-25 / 갱신: 2026-09-26 (목업 `docs/spec/ui/solar_light_dashboard_v15.html` 의 틀·색·간격으로 재구성, 대시보드·등록승인 화면 추가)
- 코드: `frontend/`. 실행법은 `frontend/README.md`.

## 목적

REST API(`docs/05`)가 돌려주는 것을 3차 최소 관리자 화면(사양서 §3.9.2: 단말 목록 / 승인·설정)으로 조작하고,
**운영 화면(7차)의 틀을 목업과 같은 자리·크기로 미리 잡아 둔다.** 백엔드가 아직 없는 카드는 같은 자리에
"준비 중 (N차)" 만 보인다 — 데이터를 지어내지 않는다.
Vite + React + TypeScript, UI·차트 라이브러리 없이 `fetch` 와 CSS 만 쓴다(빌드 gzip 약 63 KB). 인증은 4차 전.

## 디자인 규칙 (목업 v15 머리말 그대로)

- 글자 4종 12/13/15/20, 굵기 400/600, 간격 4/8/12/16, 모서리 카드 12 / 안쪽 8 / 알약 999.
- 그리드 왼쪽 넓은 열 : 오른쪽 좁은 열 = 2.4 : 1 (`.content`). 1280px 이하는 1열.
- 색은 전부 `style.css` 의 CSS 변수(목업의 `--bg --panel --soft --line --ok --warn --alarm --off --lamp --use …`).
  어두운 화면 기본, 헤더 ☀/☾ 로 전환(`localStorage slc-theme`, 목업과 같은 키). 글꼴 Noto Sans KR(Google Fonts).
- 목업의 클래스 이름을 그대로 쓴다: `aside.side > nav.nav`, `header.top`, `.content > section.card > .ch/.cb`,
  `.keys/.key`, `.sbar`, `.hist`, `.tabs/.queue`, `table.list`, `.badge.b-*`, `.bt`, `.pager`,
  `aside.drawer.wide > .dh/.db > .sec/.grid2/.met`, `.steps`, `.form2`, `.log`, `.ph`(자리표시, 추가).

라우팅은 `location.hash` 만. 요약(counts·health)은 10초, 대시보드 표본은 30초마다 갱신. 헤더 "새로고침"으로 즉시.

## 필요한 API 추가 (백엔드 요청)

1. `GET /api/events?limit=&kind=&since=` — 전체 단말 최근 이벤트(대시보드 "최근 이벤트"). 지금은 단말별 `…/{uuid}/events` 만.
2. `GET /api/devices/summary` 또는 목록 API 의 `counts` 확장 — `lamp_on / lamp_off / battery_buckets` 집계. 지금은 ACTIVE 최대 500대 표본으로 계산(1만 대면 표본 표시).
3. `GET /api/rollup/daily?from=&to=` — 발전·사용 일 집계 조회(7차 발전과 사용·에너지 합계).
4. `GET /api/regions` — 법정동별 단말 수·좌표(7차 지도, 목업 `REGIONS`).
5. 조치 필요의 "오프라인" 은 ACTIVE 표본 안에서만 본다 → `GET /api/devices?state=ACTIVE&online=false` 로 total 만 받으면 정확한 수를 낼 수 있다(이미 가능, 화면 반영은 다음).

## docs/05 에 없어서 가정한 것 (백엔드와 맞출 것)

- `counts` 는 필터와 무관한 전체 기준(docs/05 명시) → 요약·대시보드에 그대로 쓴다.
- `PATCH …/config` 응답의 `published=false` 사유 필드명 `reason`(`NOT_ACTIVE` 등).
- `PATCH …/profiles/{id}` 응답 = `ProfileOut + bumped_devices`.
- 이벤트 payload 키(STATE_CHANGE 의 `from`/`to`, CONFIG_ACK 의 `result` 등)는 몇 가지 후보 키로 요약, 없으면 원본 JSON.
- 등록·승인 화면의 "보낼 CONFIG_SET" 은 docs/05 규칙(`cv_server==0 → 1`, `cv_device` 가 더 크면 `+1`)으로 화면에서 계산한 예상값이다. 실제 발행값은 첫 Telemetry 때 서버가 만든다.

## 왜 "발행함"과 "단말이 받음"을 따로 보이나

사양서 §1.1.10: 단말은 LTE NAT 뒤라 서버가 보낸 것은 **단말이 다음에 송신한 직후**에야 도착한다(최대 ti 약 5분).
승인(REGISTER_ACK retain)은 단말의 첫 Telemetry 로, CONFIG 는 CONFIG_ACK 와 Telemetry `cv` 로 확인한다.
화면은 서버가 발행한 시각과 단말이 실제로 받았다는 증거를 같은 줄에 섞지 않는다.
