# 07. 프론트엔드 (개발용 최소 화면)

- 작성일: 2026-09-25
- 코드: `frontend/`. 실행법은 `frontend/README.md`.

## 목적

2차 REST API 가 실제로 무엇을 돌려주는지 사람이 눈으로 확인하는 **개발용** 화면.
디자인·지도·차트·인증 없음. Vite + React + TypeScript, UI 라이브러리 없이 `fetch` 만 쓴다.
운영 화면(대시보드·지도)은 7차, 인증은 3차에서 따로 붙는다.

## 구조

```
frontend/
  vite.config.ts        dev 프록시: /api, /health → http://localhost:8000 (포트 5173)
  src/api.ts            REST 호출·타입·에러 파싱
  src/format.ts         단위 변환(x100), er 비트, 상대시간
  src/App.tsx           요약바 + 탭 + 좌우 분할(master-detail)
  src/DeviceList.tsx    왼쪽 목록
  src/DeviceDetail.tsx  오른쪽 상세·동작·이력
  src/ImportAccounts.tsx 관리 탭(계정 CSV import)
```

파일 탐색기처럼 **왼쪽 목록에서 고르면 오른쪽에 상세**가 뜨는 구조. 라우팅은 `location.hash`
(`#devices` / `#admin`) 만. 10초마다 자동 갱신.

## 화면

| 영역 | 내용 | API |
|---|---|---|
| 요약바 | 전체/온라인/오프라인, state 별 수, mqtt_connected·db_ok·telemetry_dropped | `GET /api/devices?size=500` 반복, `GET /health` |
| 장치 목록 | uuid, state, online(●/○), site, 마지막 TM 상대시간, bv/sc. state·online 은 서버 필터, 텍스트는 페이지 내 필터. page/size | `GET /api/devices` |
| 상세 | 기본정보 / LTE·SIM / 설정 / 상태 그룹별 정의목록, 마지막 텔레메트리(단위 변환·er 비트·md 라벨) | `GET /api/devices/{uuid}` |
| 동작 | 설정 변경(ti/lat/lon/site), PING → PONG 이벤트 폴링(8초), 삭제(confirm) | `PATCH …/config`, `POST …/ping`, `GET …/events?kind=PONG`, `DELETE …` |
| 이력 | 최근 텔레메트리 50건, 이벤트 50건(payload JSON) | `GET …/telemetry?limit=50`, `GET …/events?limit=50` |
| 관리 탭 | 계정 CSV 업로드 → 결과 JSON | `POST /api/devices/import-accounts` |

오류는 `{error:{code,message}}` 를 그대로 빨간 줄로 보여준다. REGISTER 전 단말은 대부분 null 이라 `-` 로 표시.

## 알아둘 것

- 목록 API 는 `last_telemetry` 를 안 주므로 목록의 bv/sc 열은 지금 비어 있다(상세에서만 보임).
  필요하면 목록 API 에 최신값 몇 개를 실어주는 쪽이 낫다(N+1 호출 금지).
- 요약 집계는 전체 목록을 500개씩 다 읽어 클라이언트에서 센다. 수천 대 넘으면 서버 집계 API 로 바꾼다.

## 3차에서 추가할 것

- PENDING 목록과 **승인/거부/중지 버튼** (`POST /api/devices/{uuid}/state`)
- 로그인(`POST /api/auth/login`) 과 토큰 첨부
- 운영 서빙: `npm run build` 결과 `dist/` 를 nginx 가 서빙하고 `/api` 를 백엔드로 프록시(compose 반영)
