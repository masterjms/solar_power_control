- 코드: `frontend/`. 실행법은 `frontend/README.md`.

## 목적

REST API(`docs/05`)가 돌려주는 것을 3차 최소 관리자 화면(사양서 §3.9.2: 단말 목록 / 승인·설정)으로 조작하고,
**운영 화면(7차)의 틀을 목업과 같은 자리·크기로 미리 잡아 둔다.** 백엔드가 아직 없는 카드는 같은 자리에
"준비 중 (N차)" 만 보인다 — 데이터를 지어내지 않는다.
Vite + React + TypeScript, UI·차트 라이브러리 없이 `fetch` 와 CSS 만 쓴다(빌드 gzip 약 63 KB). 인증은 4차 전.

## 디자인 규칙 (목업 v15 머리말 그대로)

- 글자 4종 12/13/15/20, 굵기 400/600, 간격 4/8/12/16, 모서리 카드 12 / 안쪽 8 / 알약 999.
- 그리드 왼쪽 넓은 열 : 오른쪽 좁은 열 = 2.4 : 1 (`.content`). 1280px 이하는 1열.
- 색은 전부 `style.css` 의 CSS 변수(목업의 `--bg --panel --soft --line --ok --warn --alarm --off --lamp --use …`).
  어두운 화면 기본, 헤더 ☀/☾ 로 전환(`localStorage slc-theme`, 목업과 같은 키). 글꼴 Noto Sans KR(Google Fonts).
- 목업의 클래스 이름을 그대로 쓴다: `aside.side > nav.nav`, `header.top`, `.content > section.card > .ch/.cb`,
  `.keys/.key`, `.sbar`, `.hist`, `.tabs/.queue`, `table.list`, `.badge.b-*`, `.bt`, `.pager`,
  `aside.drawer.wide > .dh/.db > .sec/.grid2/.met`, `.steps`, `.form2`, `.log`, `.ph`(자리표시, 추가).

## 화면 문구 — 사용자 말 (2026-10-01, 문제점 22번)

화면에 보이는 말은 개발 용어 대신 아래를 쓴다. **코드 이름·API·해시 경로(`#schedule`, `#profiles`)·이 문서의 아래 절들은 옛 이름 그대로**다(읽을 때 이 표로 바꿔 읽는다). 새 화면은 처음부터 이 말로 쓴다.

| 코드·옛 문구 | 화면 문구 |
|---|---|
| 스케줄 배포 | 그룹 스케줄 변경 |
| 스케줄 프로필 | 스케줄 양식 |
| 배포 / 배포 작업 | 보내기 / 보낸 기록 |
| (스케줄) 배정 | 지정 — 단말을 지역에 넣는 "배정·미배정"은 그대로 |
| 프로필(설정) — ti·ka | 통신 주기 설정 |
| 노드 / 말단 | 지역 / 동 |
| 원격 override | 원격 조작 |
| 동기 / 단말 값이 바뀜 | 단말과 같음 / 단말과 다름 |
| seq · ACK · payload · topic | 명령 번호 · 응답 · 보낸 내용 · 보낼 주소. 원문 JSON·주소 목록은 "자세히"로 접음 |

남긴 것: `REGISTER_ACK` 같은 메시지 이름(승인 창·단말 상세 버튼), 알람 탭 "설정 불일치"(서버 알람 이름과 같은 글자여야 함), 시스템 화면(개발자용).

## 글자 규칙 (2026-10-03, 문제점 26번)

글꼴은 `--font`(Noto Sans KR) 하나, 코드·식별자만 `--mono`. 크기는 토큰 다섯 개만, 굵기는 400·600 둘만. **style.css 에서만** 정하고 화면 파일(tsx)의 인라인 `fontSize`·`fontWeight`·`fontFamily` 는 금지 — `tools/tests/test_frontend_style_rules.py` 가 막는다.

| 역할 | 토큰 | 크기/굵기 | 쓰는 곳 |
|---|---|---|---|
| 페이지 제목 · 큰 숫자 | `--f4` | 20 / 600 | 상단 제목, 대시보드 집계 숫자 |
| 카드·창 제목 | `--f3` | 15 / 600 | 카드 머리, 드로어·모달 제목 |
| 본문 · 입력 · 표 셀 · 절 제목 | `--f2` | 13 / 400(절 제목 600) | 거의 전부 |
| 보조 · 캡션 · 표 머리 · 배지 · 버튼 | `--f1` | 12 / 400(배지 600) | 설명 줄, 단위, 출처 |
| 폰 입력칸 | `--f-touch` | 16 | 로그인(16 미만이면 iOS 가 확대) |

새 역할이 필요하면 토큰을 먼저 추가하고 이 표에 적는다. 전체 크기를 키우려면 토큰 값만 바꾼다(`--f2` 13→14 등).

## 오프라인 단말 조작 (2026-10-03, 문제점 32번)

`is_online` 이 아니면 **단말이 받아야 하는** 버튼을 막는다(툴팁 "오프라인 — 다시 접속하면 …"): 원격 명령(소등·점등·밝기·복귀)·원격 조작 해제·PING·단말에서 읽기/쓰기/되돌리기·단말 하나 다시 보내기.
서버 안에서 끝나는 것은 그대로: 승인·중지·복귀·거절·폐기, REGISTER_ACK 재발행, 설정 변경(CONFIG_SET 은 단말이 다음 송신 때 받음), 삭제, 미리보기, 양식·지정, 지역 단위 보내기(오프라인은 대기 → 재접속 때 자동), 그룹 명령(오프라인은 안 보냄).
단말 상세의 `ti_override`·`ka_override` 입력은 뺐다(28번) — 남아 있는 값은 "주기 설정 값으로" 버튼으로만 지운다.

### 단말 등록·승인 (`#pending`) — 2026-09-28 문제점 #4·#6 개정
**승인 대기 목록만** 남겼다(거부·상세 버튼, 오른쪽 "승인"·"승인하면 보내는 것"·"단말 등록" 카드 삭제). 행을 누르면 **승인 전용 창**(`Approval.tsx`, 드로어 자리)이 열린다. 단말 목록·대시보드 등 **어디서 골라도 PENDING 단말이면 같은 승인 창**(App 의 `DeviceDrawer` 가 state 로 가른다). 승인 창은 위에서 아래로:
1. **단말기 정보** — 모델·펌웨어·모뎀·IMEI·ICCID·MSISDN·최초 접속·마지막 수신

3. **프로필**
4. **설정 변경** — 2·3 에서 바꾼 것만 `PATCH …/config`

### 5차 API 가정 (백엔드와 병행 개발 — 타입과 `npm run build` 로만 맞췄고 실제 API 로는 아직 안 돌려 봤다)

- `GET /api/regions` 의 `level` 은 `sido|sigungu|dong`. 말단 판정 = `level==="dong"` 또는 (`bjd_code` 있고 자식 없음).
- 트리 노드 id 는 숫자, 명령 `target.id` 는 **문자열**(`"3"`) — docs/05 예시대로.
- `from-address`·`PATCH /regions/{id}` 응답 = Region 한 줄(`id`, `name`, `bjd_code` 사용).
- `GET /api/commands` 는 배열(페이지 객체 아님). `counts` 에 없는 키는 0 으로 본다. 진행 중이면 `finished_at=null`, `result=null`.
- 결과 "오류" = `BAD + STATE`, "무응답" = `pending`. 재시도는 `{uuids:null}`(무응답·만료 전부).
- `DeviceOut.remote_remaining_sec` 는 초. 화면은 분 올림. `override_level` 은 문자열 그대로 표시.
- `/api/me` 가 없거나 실패하면 관리자 취급. "오늘 밤" 은 `dur_preset:"tonight"` 으로 보내고 계산은 서버.
- 에러 코드(`FORBIDDEN`·`GEO_UNAVAILABLE`·`REGION_IN_USE`·`NODE_NOT_LEAF`·`NODE_REQUIRED`·`REGION_NOT_FOUND`·`COMMAND_NOT_FOUND`·`COMMAND_FINISHED`·`NO_TARGETS`·`MQTT_UNAVAILABLE`)는
  `errorText` 가 한국어 한 줄을 앞에 붙이고 원문을 뒤에 둔다.
- 화면 확인은 dev 서버 + 브라우저에서 5차 응답을 가짜 fetch 로 흉내 내 레이아웃·흐름만 봤다(트리 펼침, 확인 창, 결과 표, 드로어, 목록 배지, GEO 503 → dev 입력 폼).
  **실제 백엔드로 끝까지(발행 → COMMAND_ACK 집계 → 재시도) 돌려 본 것은 아니다.**

### S-23 단말 설정 API 가정 (백엔드와 병행 — 타입과 `npm run build`, 가짜 fetch 로 흐름만 확인)

- `GET /api/settings/schema` = `ui_items.json` 그대로(`groups/rules/calc/year_table`).
- `GET …/settings` 모양은 docs/05 그대로. `tbl.crc_expected`·`tbl.matches` 는 null 가능(비교 불가 표시). `diff` 는 배열(없으면 `[]`).
- `POST …/read`·`PUT`·`POST …/revert` 응답 = `{seq, sent_at[, sh_expected, payload_bytes]}`. `accept` 응답은 쓰지 않는다(다시 GET).
- 422 `detail.key` = 항목 키 또는 표 조건 `"tbl.lat"` 꼴(`detail.field` 로 와도 받는다) → 그 칸 아래 표시. `detail.rule` = `rules[].id` → 규칙 줄.
- 표 조건 입력 key 는 `year_table.inputs` 의 `region/lat/lon/on_corr/off_corr`, PUT 본문은 `{region, lat, lon, on, off}`(lat/lon 실수).
- 쓰기 대기 판정: `pending` 이 있거나 `sync == "writing"` 이면 3초 폴링, 보낸 seq 가 `pending` 에서 빠지면 끝. 3회 무응답의 결과(`TIMEOUT` 등)는 `last_result` 로만 본다.
- 이력 `by` 는 `device_read` / `server_write` / 사용자 이름. 이벤트 kind 이름은 모름 → `SETTINGS` 가 든 kind 만 걸러 보인다.
- `force=true`(읽지 않은 단말에 쓰기)는 화면에 두지 않았다 — 읽고 나서 쓴다.
- 지역 목록 36곳 고르기(명세 §3.1)는 목록 API 가 없어 직접 입력만.

### 아직 안 한 것 (5차 화면)
- 등록 때 말단을 고르면 좌표를 그 법정동 중심으로 채우는 것(목업 #rdrawer) — `PATCH /state` 가 lat/lon 을 받지 않아 뺐다. 좌표는 드로어 설정에서.
- 단말 목록의 지역(node_id) 필터 — API 는 있음, 화면은 지역 페이지의 "이 지역 단말"로 대신.
- 결과 표는 한 번에 300대까지만 그린다(상태 탭으로 좁힘). 1만 대 전체 명령의 대상 목록 페이지네이션은 API 가 생기면.

## 왜 "발행함"과 "단말이 받음"을 따로 보이나

사양서 §1.1.10: 단말은 LTE NAT 뒤라 서버가 보낸 것은 **단말이 다음에 송신한 직후**에야 도착한다(최대 ti 약 5분).
승인(REGISTER_ACK retain)은 단말의 첫 Telemetry 로, CONFIG 는 CONFIG_ACK 와 Telemetry `cv` 로 확인한다.
화면은 서버가 발행한 시각과 단말이 실제로 받았다는 증거를 같은 줄에 섞지 않는다.
