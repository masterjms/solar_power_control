# ADR-005 5차 — 법정동 트리, COMMAND 발행·응답·재시도, 권한

- 날짜: 2026-09-27
- 상태: 확정 (사양서 2026-09-27 "다음 전달 범위" S-15 ~ S-20, §3.9.3, §3.10)
- **2026-09-28: override 계층(개별 > 그룹 > 전체) 부분은 ADR-008 로 대체** — 단말 F/W -9 가 "채널마다 마지막 명령 하나"로 바꿨다.

## 결정

### 그룹 = 말단 법정동 (S-15)
- `region` 트리: 시도 > 시군구 > 법정동(말단). 말단만 `bjd_code`(카카오 로컬 `b_code` 앞 10자리)를 가진다.
- `group_id` = `bjd_code` + `"00"` (12자리). 단말당 1개. `device.node_id`(말단) 배정 시 `device.grp` 를 같이 갱신(비정규화 — REGISTER_ACK 발행을 빠르게).
- `grp` 는 **retain REGISTER_ACK** 에만 싣는다(`state`·`site`·`grp` 한 메시지). CONFIG_SET 에는 넣지 않는다. 바뀌면 retain 을 다시 발행.
- 말단 추가는 카카오 주소 검색 → `b_code`·시도·시군구·동 이름·좌표로 **상위 노드까지 find-or-create**. 운영자가 코드를 손으로 치지 않는다. 카카오 키가 없는 개발 환경에서만 `bjd_code` 직접 입력을 허용(`APP_ENV=dev`).
- 승인(ACTIVE)에는 말단 배정이 필요하다(`APPROVE_REQUIRES_NODE`, 운영 기본 true). 개발 compose 는 false(3차 시나리오 호환).

### COMMAND (S-16)
- payload: `{"type":"COMMAND","seq","ts","exp","act","ch"[,"pwm"][,"dur"]}` — `type` 은 `COMMAND`(CMD 아님), **`ts` = 보낸 시각 `YYMMDDThhmmss` KST**, `exp` 기본 30(`COMMAND_EXP_SEC`), `ch` 기본 `[1,2]`, `pwm` 은 `ch` 와 같은 길이, `dur` 1~86400(`auto` 는 없음).
- 대상: 개별 `device/<uuid>/cmd` / 트리 노드(말단 = 그 그룹 topic 1회, 상위 = 하위 말단마다 1회) / 전체 `all/cmd`(**최고관리자만**).
- 한 번의 관리자 명령 = `seq` 하나. 상위 노드 명령이 topic n개로 나가도 seq 는 같다(단말은 한 그룹만 구독하므로 중복 수신 없음).
- 보낼 때 대상 단말 목록을 `command_target` 에 **스냅숏**한다(ACTIVE 단말만. PENDING 등은 STATE 로 거부할 것이므로 제외).

### COMMAND_ACK·재시도 (S-17, S-18)
- `COMMAND_ACK.result` ∈ OK / LOCAL / EXPIRED / BAD / STATE → `command_target.status`.
- 재시도는 **그룹 재발행 금지, 개별 topic 으로 같은 seq·새 ts**. 같은 seq 라 이미 받은 단말은 첫 결과로 ACK(단말 최근 8개 기억).
- **자동 재시도 시점 = 그 단말이 뭔가 보낸 직후**(§1.1.10, S-12 와 같은 원리). `pending`·`EXPIRED` 대상이 REGISTER/TELEMETRY 를 보내면, 명령이 아직 유효(`sent_at + dur` 전, `auto` 는 `COMMAND_TIMEOUT_SEC`)하고 시도 수 < `COMMAND_MAX_ATTEMPTS`(3)이며 마지막 발송 후 `COMMAND_RETRY_MIN_SEC`(20) 지났으면 다시 보낸다. `exp` 30초 + 전달 지연(최대 5분) 조합에서 생기는 EXPIRED 를 이 경로가 흡수한다.
- 수동 재시도 버튼도 둔다(무응답·EXPIRED 만).
- 명령 종료: 모든 대상이 종결 상태(OK/LOCAL/BAD/STATE, 또는 시도 소진한 EXPIRED)거나 `COMMAND_TIMEOUT_SEC`(900) 경과. `result` = OK(전부 OK) / PARTIAL / TIMEOUT(응답 0). LOCAL 은 "받았지만 현장 조작 중" — 종결로 본다.

### override 표시 (S-19)
- OK 응답 시 `device.override_act/level/seq/until` 기록. `until = ts(보낸 시각) + dur`. `act=auto` 는 해당 계층 해제(개별 auto 면 전부 NULL).
- 표시: `remote_active = last_telemetry.md == 2 AND override_until > now`, 남은 분. 재부팅 감지(sq 감소) 시 override 필드 NULL(단말이 잃는다).

### 권한 (§3.9.3 #9)
- 로그인 기능 전까지 nginx Basic auth 사용자명을 `X-Remote-User` 헤더로 백엔드에 넘긴다(백엔드는 호스트에 노출되지 않으므로 신뢰).
- `SUPER_ADMIN_USERS`(쉼표, 기본 `admin`) = 최고관리자: 전체 명령, 트리 편집. 그 외 = 관리자.
- 헤더가 없으면(개발 PC 에서 8000 직접) `APP_ENV=dev` 일 때만 최고관리자 `local`, 아니면 관리자 `anonymous`.
- 명령 이력의 "누가" = 이 사용자명.

## 결과
- 1만 대·법정동 수백 개 규모에서 상위 노드 명령 = 발행 수백 번 — 문제없다(사양서 §3.10.4).
- "오늘 밤" 유지시간: `docs/spec/ref/suntable.py` 로 대상(말단 좌표, 없으면 서울) 오늘 소등(일출 쪽) 시각까지 남은 초. 1~86400 으로 자른다.
