# ADR-008 원격 표시는 채널마다 마지막 명령 하나 (F/W 2026-09-27-9)

- 날짜: 2026-09-28
- 상태: 확정 (사양서 2026-09-27 개정 §3.10.8 "채널마다 마지막 명령 하나", 문제점 리스트 260928 함께 수령)
- 바꾸는 것: ADR-005 의 "override 슬롯 계층(개별 > 그룹 > 전체)" 부분

## 배경

5차 첫 설계(단말 -8 까지)는 개별·그룹·전체 계층마다 (값, 만료)를 따로 두고, 적용값은 유효한 슬롯 중 최상위였다.
개별이 끝나면 아직 유효한 그룹/전체 명령으로 돌아갔다. 실기(C5)에서 "끝난 줄 안 명령이 30초 뒤 다시 살아나는" 동작이
오히려 혼란스러워 단말이 바꿨다(사용자 결정, F/W 2026-09-27-9).

## 결정

### 단말 규칙(사양서 §3.10.8)
- 채널마다 **(값, 만료) 하나.** 개별·그룹·전체 어느 경로로 왔든 **나중에 온 명령이 덮는다.** 경로 사이 우선순위 없음.
- 유지시간이 끝나면 그 채널은 **스케줄**. 이전 명령을 되살리지 않는다.
- 다른 채널은 서로 건드리지 않는다(주등 on 뒤 입간판 off 가 와도 주등 그대로).
- `auto` = 그 명령 `ch` 의 채널을 스케줄로. 현장 조작 시작·재부팅 = 전부 소거.

### 서버 기록(DB 0005)
- `device.override_ch` jsonb `{"<채널>": {act, seq, until, level}}`. OK 응답마다 `core/command_rules.channels_after_ok`:
  명령 `ch` 채널마다 — 기록이 **더 새 seq** 면 그대로(늦게 도착한 옛 재시도 OK 가 새 명령을 덮지 않게), 아니면 auto 는 지우고
  on/off/pwm 은 `until = 보낸 시각 + dur` 로 덮는다. 끝난 채널은 그때 버린다. `level` 은 경로 기록일 뿐.
- 기존 `override_act/level/seq/until` 은 **요약**(가장 늦게 끝나는 채널)으로 같이 쓴다(`core/override.apply_channels`) —
  목록 필터 `remote=true` 와 "원격 n분 남음"이 바뀌지 않는다.
- 재부팅(sq 감소)·현장 조작(TM md 1): 그 TM 을 받은 시각 **이전에 보낸** 명령의 채널만 지운다(flush 지연 중 들어온 새 명령은 남긴다).
- `DeviceOut.override_ch` = 채널별 `{act, seq, level, remaining_sec}`(끝난 채널 빠짐).

### 시험
- 단위: `backend/tests/test_command_rules.py` (경로 무관 나중 승, 옛 seq 무시, 채널 독립, auto 채널만, 만료 정리, 요약).
- 시뮬레이터 `tools/sim/device.py` 슬롯을 채널 키로 바꿈. 시나리오 **S5-05 개정**(만료 → 스케줄, 채널 독립, 서버 override_ch).

## 결과
- 화면의 "원격 n분 남음"은 가장 늦게 끝나는 채널 기준이다. 채널별 남은 시간은 `override_ch` 로 볼 수 있다(드로어에 넣을 수 있음).
- 전체 소등 중 한 대를 개별 점등으로 점검하면, 끝난 뒤 그 한 대는 **스케줄**로 간다(전체 소등으로 돌아가지 않는다).
  다시 끄려면 새 명령을 보낸다 — 서버 명령 이력으로 안다.
