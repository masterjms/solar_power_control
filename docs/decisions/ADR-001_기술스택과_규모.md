# ADR-001 기술 스택과 규모 전제

- 날짜: 2026-09-25
- 상태: 확정

## 맥락
사양서는 언어/프레임워크를 서버 담당 선택으로 남겼다. 기준은 "Broker 재시작 후 자동 재구독, DB 저장 실패 시 로그". 목표 규모 1만 대, 이력 1년.

## 결정
- Python 3.12 + FastAPI + aiomqtt + SQLAlchemy 2 async + asyncpg + Alembic + APScheduler 3. xWIFI(`hanna_aircast_platform`)와 동일 → 검증된 MQTT 수신·계정 배포 코드를 옮겨 쓴다.
- Mosquitto 2.x 단일 인스턴스. EMQX·클러스터 없음.
- PostgreSQL. 개발은 EC2 컨테이너, 운영은 RDS. Timescale 안 씀 — 네이티브 월 파티션이면 5억 행/년 감당.
- 백엔드 단일 프로세스. `$share` 구독·워커 풀 없음.

## 근거
- 1만 대 × 10분 = 17 msg/s. aircast 버퍼 경로 실측 12k msg/s.
- 단일 프로세스의 약점은 처리량이 아니라 **재접속 폭주 시 응답 발행량**과 **DB 장애 시 적체**. 이 둘은 토큰 버킷과 "실패 시 폐기"로 다룬다.

## 결과
- 수만 대로 커지면: 이력을 Timescale/별도 DB 로, 브로커를 EMQX 로, 수신을 공유 구독 다중 워커로. 그때까지는 안 한다.
