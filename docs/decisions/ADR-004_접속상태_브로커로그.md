# ADR-004 Online/Offline — LWT 대체, 브로커 로그 + 수신 시각

- 날짜: 2026-09-26
- 상태: 확정 (사양서 §16.1 2026-09-26 개정 반영)

## 맥락
WD-N522S 모뎀은 Will(LWT)을 넣지 못한다. keepalive(300초 확정)는 넣으므로 브로커는 끊김을 알지만(×1.5 = 7.5분),
그 사실을 서버에 알릴 topic 이 없다. 사양서는 방법 A(Mosquitto 로그), B(연결 이벤트 브로커), C(수신 시각 보조) 중 서버가 고르라고 했다.

## 결정
- **A + C.** Mosquitto 가 `log_dest file /mosquitto/log/mosquitto.log` 로도 쓰고(stdout 유지), 그 파일을 공유 볼륨으로 백엔드가 tail 한다(`app/tasks/broker_log.py`).
  - `New client connected from <ip> as <UUID> (... u'<UUID>')` → `online=true`, `device_event(ONLINE)`
  - `Client <UUID> ... disconnected` / `Client <UUID> has exceeded timeout, disconnecting.` → `online=false, offline_at`, `device_event(OFFLINE)`
  - client id 가 UUID 형식이 아닌 줄(백엔드·healthcheck·시험 도구)은 무시.
  - 파일 회전: entrypoint 감시 루프가 50 MB 넘으면 truncate 하고 mosquitto 에 HUP(로그 재오픈). tail 은 inode/크기 감소를 보고 처음부터 다시 읽는다.
- C 는 항상 같이 둔다: `last_seen_at < now - ti×3` 이면 OFFLINE 으로 본다(PENDING 은 70분). 화면은 "MQTT 상태 / 마지막 수신" 을 나눠 보여 준다.
- 기존 `LWT` 처리는 남겨 둔다 — 시뮬레이터나 후속 모뎀이 Will 을 넣으면 그대로 동작한다.

## 결과
- 감지 7.5분(keepalive 300)은 사양서가 받아들인 값이다.
- 브로커 이미지가 go-auth 로 바뀌어도(ADR-003) 로그 형식은 Mosquitto 2.0.x 그대로다. 로그 파서에 단위 테스트를 둔다(형식이 바뀌면 여기서 잡힌다).
- 백엔드 재시작 시 tail 위치를 잃는다 → 기동 때 파일 끝부터 읽고, `online` 은 C 규칙이 보정한다. 브로커 재시작 시 전 단말이 재접속하므로 로그로 다시 맞춰진다.
