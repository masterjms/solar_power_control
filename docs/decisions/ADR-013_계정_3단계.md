# ADR-013 계정 3단계 — 최고관리자 / 지역관리자 / 게스트, 접근 검사 한 곳

- 날짜: 2026-10-04
- 상태: 확정 (문제점 21번 — 단말측 2차안 + 서버 검토 의견, 10/3 단말측 회신으로 확정)

## 배경
계정이 `.env` 의 2개(최고관리자·관리자)뿐이었다. 시·도 단위로 관리를 나눠 주고(지역관리자), 대시보드만 보여 줄 계정(게스트)이 필요하다.
단말측 확정: 최고관리자 3명, 지역관리자에게 시·도 여러 개, 스케줄 양식 공용, 게스트 행 클릭 없음, 단말 삭제는 최고관리자만, 비밀번호 8자 이상, 사용 기간 7·15·30·90·180일·1년·무한.

## 결정
### 계정
- DB `admin_user`(3차에 만들고 안 쓰던 표를 넓힘, 0011): 아이디·비밀번호 해시(PBKDF2-SHA256 240,000회, 표준 라이브러리)·역할·맡은 시·도(`region_ids`, 트리 최상위 id 배열)·만료·사용 중지·만든 사람·마지막 로그인·비밀번호 바꾼 시각.
- `.env` 의 ADMIN_USER(최고관리자)·OPERATOR_USER(옛 "관리자" = 전 지역, 최고관리자 아님)는 그대로 쓴다. 화면에서 바꾸거나 지울 수 없고 같은 이름을 만들 수 없다.
- 최고관리자는 `.env` 포함 **3명까지**. 자기 자신의 최고관리자 권한은 내리거나 중지·삭제할 수 없다(잠김 방지).
- 사용 기간이 지나거나 사용 중지되면 **로그인도, 이미 받은 로그인 쿠키도** 거부(쿠키 판정 /api/auth/check 가 매번 DB 를 본다). 자동 삭제는 없다 — 연장·삭제는 최고관리자.
- 비밀번호를 바꾸면(본인·재설정) 그 전에 받은 쿠키를 끊는다: 쿠키의 발급 시각 < `password_changed_at`. 쿠키는 초 단위라 바꾼 시각을 다음 정수 초로 올려 둔다.
- 로그인 성공·실패는 `login_log`(1년 보관).

### 접근 검사는 한 곳 — `core/access.access_guard`
모든 API 라우터에 의존성으로 건다(로그인 `/api/auth/*`·브로커 내부 `/internal/mqtt/*` 제외). 요청마다:
1. 누구인가(`core/auth.current_user`): 헤더 → `.env` 규칙 → DB 계정(만료·중지면 401 SESSION_ENDED).
2. **지역 범위** = 맡은 시·도 아래 전체 노드 id → contextvar. 목록 조회는 `in_scope(Device.node_id)` 한 줄로 거른다(단말 목록·집계·지도·오늘 전력량·알람·명령 이력·스케줄 적용 현황·보낸 기록·발전 통계·지역 트리). 스케줄러·MQTT 처리는 범위 없음(전 지역).
3. 게스트는 대시보드에 필요한 GET 표(`GUEST_ALLOW`)와 자기 비밀번호만 — 나머지 403 `GUEST_READ_ONLY`.
4. 최고관리자 전용 표(`SUPER_ONLY`): 서버 설정·서버 상태·`/api/metrics`·관리 API·통계 다시 시작·통신 주기 설정 쓰기·지역 이름/삭제·단말 삭제·계정 관리.
5. 경로에 `{uuid}` 가 있으면 그 단말이 범위 안인지 — 아니면 **404**(있다는 것도 알리지 않는다). 예외: 지역이 없는 승인 대기 단말은 uuid 로 연다(아래 6자리 검색 → 승인).
본문에 노드·단말이 들어오는 쓰기는 서비스에서 `check_node`/`node_allowed`: 명령 대상, 단말 지역 바꾸기·승인(지역관리자는 동 필수), 스케줄 지정·보내기, 지역 추가(맡은 시·도 밖이면 403 `OUT_OF_REGION`, 새 시·도는 못 만든다), 보낸 기록·명령 상세(범위 밖이면 404).

### 화면
- 메뉴: 최고관리자 전부 + "계정 관리"·"서버 상태". 지역관리자는 통신 주기 설정·서버 설정·서버 상태·계정 관리가 없다. 게스트는 대시보드만(행 클릭·상세·다른 화면 링크 없음, 지도는 움직인다). 주소창으로 없는 메뉴에 가면 대시보드로.
- 승인 대기: 최고관리자는 목록, 지역관리자는 **UUID 뒤 6자리 이상 검색** — 1대면 승인 창, 여러 대면 "N대가 같은 번호 — 자리 수를 늘려" 안내(고르게 하지 않는다 — 남의 단말일 수 있다).
- 스케줄 양식: 공용(누구나 보고 지정), 고치기·지우기는 만든 사람과 최고관리자.
- 위 막대: 아이디·역할·맡은 시·도, 화면에서 만든 계정은 "비밀번호" 버튼. HMAC·공용 시험 계정 알약은 최고관리자에게만.

## 버린 것
- 라우터마다 권한 코드를 넣기: 60여 곳에 흩어지면 하나만 빠져도 샌다. 공통 검사 + 목록 조회 한 줄로 모았다.
- 범위 밖 단말에 403: 존재 여부가 드러난다 → 404.
- bcrypt 등 외부 패키지: PBKDF2(표준 라이브러리)로 충분하고 이미지에 패키지를 더하지 않는다.
- 업자별(지역 겹침) 계정: 단말측 결정으로 지원하지 않음(21번 1차 검토).

## 결과
- 로컬 nginx 로그인 경로로 세 역할 47개 확인(docs/reports/2026-10-04_계정_서버상태.md).
- 배포 때 DB 변경 1회(0011), 단말 영향 없음. 기존 `.env` 계정·시험 도구(X-Remote-User)는 그대로 동작.
