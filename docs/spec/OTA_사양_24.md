# 사양서 §24 OTA (원격 펌웨어 갱신) — 사본

> 원본: 단말측 저장소 `spec/server/태양광_조명_서버_관제_사양_v1.0.md` §24 (커밋 53ae7f8, 2026-10-17 확정, 단말 실기 검증).
> 문제점 시트 56번 탭에서 옮김(2026-10-18). 원본이 바뀌면 원본이 기준이다. 서버 구현: docs/05 "OTA API", docs/03 0013.

## 24.1 흐름
```text
서버 → OTA_START       iotlight/device/{uuid}/cmd  (단말 개별 topic 만)
단말 → OTA_ACK START   iotlight/device/{uuid}/result
단말 → MQTT 끊기(AT*WMQTDIS)   → 브로커가 바로 끊김을 앎 → 서버는 즉시 오프라인(OTA 중) 표시
단말 → HTTPS 로 pkg 를 chunk(기본 3,840) 바이트씩 나눠 받기(Range) → base64 를 풀어 단말 안 보관 영역에 저장 → 크기·SHA-256 검사
├ 실패 → MQTT 다시 접속 → REGISTER → OTA_ACK <오류>
└ 성공 → 재부팅 → 부트로더가 보관 영역(새)과 앱 영역(이전)을 맞바꿈 → 새 앱이 MQTT 접속(REGISTER, sq 0 부터)
├ 새 앱이 서버에 닿음 → OTA_ACK DONE (새 펌웨어 확정)
└ 확정 전 재부팅 3번 또는 1시간 안에 서버에 못 닿음 → 부트로더가 이전 펌웨어로 되돌림
→ 이전 앱이 MQTT 접속 → REGISTER → OTA_ACK ROLLBACK
```
되돌리기(롤백)는 단말이 스스로 한다. 서버가 되돌리라고 명령하는 기능은 없다(필요하면 이전 pkg 로 OTA 를 다시 보낸다).

## 24.2 pkg (서버가 올려 둘 파일)
| 항목 | 값 |
|---|---|
| `pkg_version` 1 | 펌웨어 `SolarLTE.bin` 전체를 **base64(표준, `=` 채움) 한 줄**로 — 줄바꿈 없이 |
| 크기 | 펌웨어 160KB 한도 → pkg 최대 218,456 바이트 |
| 제공 | `https://enerz.co.kr` 443, HTTP `Range` 지원. 단말은 `Range: bytes=a-b` 로 `chunk` 바이트씩 요청 |
| 인증서 | 단말 모뎀은 HTTPS 인증서 검증을 못 한다 → MQTT(검증된 TLS)로 받은 `sha256` 으로 확인 |
| 평문 http | 운영에서는 쓰지 않는다. 사내 PC 시험 구성에서만 |

## 24.3 메시지
**OTA_START (서버 → 단말)** — 개별 topic, QoS 1, retain 0, 한 줄 JSON
```json
{"type":"OTA_START","job_id":9001,"pkg_version":1,"url":"https://enerz.co.kr/ota/...","size":181816,"sha256":"<64 hex>","chunk":3840}
```
| key | 내용 |
|---|---|
| `job_id` | 서버가 부여한 작업 번호(32비트 부호 없음). OTA_ACK 에 그대로 돌려준다 |
| `pkg_version` | 지금은 1 만. 다른 값이면 `BAD` |
| `url` | 운영은 `https://enerz.co.kr/...` 만, 160자 이하, 영문·숫자·`/` `-` `_` `.` 만. JSON 에서 `/` 를 `\/` 로 이스케이프하지 않는다 |
| `size` | pkg 전체 바이트 수. 4 ~ 218,456, 4의 배수 |
| `sha256` | pkg 전체 SHA-256, 64자리 hex |
| `chunk` | (선택) 512 ~ 4,092, 4의 배수. 넣으면 3,840 권장 |

**OTA_ACK (단말 → 서버)** — `result` topic, QoS 1 `{"type":"OTA_ACK","uuid":"…","job_id":9001,"result":"START"}`

| `result` | 때 | 뜻 |
|---|---|---|
| `START` | 명령 직후 | 받기 시작. 이 응답 뒤 단말은 MQTT 를 끊는다 |
| `BAD` `STATE` `BATT` `BUSY` | 명령 직후 | 형식 오류 / 승인 아님 / 저전압 / 이미 OTA 중·지난 결과 못 보냄 |
| `HTTP` `SIZE` `HASH` `FLASH` | 다시 접속한 뒤 | 다운로드 / 크기 / SHA-256·base64·앱 이미지 / 저장·적용 실패 |
| `DONE` | 새 펌웨어로 접속 | 성공(확정) |
| `ROLLBACK` | 이전 펌웨어로 접속 | 실패 — 이전 펌웨어로 돌아옴 |

결과는 다시 접속한 단말이 REGISTER 바로 다음에 보낸다. `DONE`·`ROLLBACK` 은 보낼 때까지 1분마다 다시 보낸다.

## 24.4 서버 판정
| 상황 | 판정 |
|---|---|
| `START` 받음, 곧 끊김 | "OTA 중" (알람 통신 두절로 올리지 않음) |
| 명령 직후 `BAD` `STATE` `BATT` `BUSY` | 시작 안 함 |
| 다시 접속 → `HTTP` `SIZE` `HASH` `FLASH` | 실패(이전 펌웨어 그대로) |
| 다시 접속 → `DONE` | 성공 |
| 다시 접속 → `ROLLBACK` | 실패 — 이전 펌웨어로 동작 중 |
| `START` 뒤 1시간 30분 넘게 결과 없음 | "응답 없음" → 현장 확인 |
| `START` 도 안 옴(30초) | 다시 보내기 3회까지(같은 job_id), 그래도 없으면 "응답 없음" |

## 24.5 서버가 할 것 (확정)
- URL 보안: 단말·명령마다 다른 서명 주소 `https://enerz.co.kr/ota/<명령번호>/<UUID>/<서명>`, 유효 2시간 안 Range 이어받기 허용, 파일은 웹 공개 폴더 밖. `sha256` 은 반드시 서버가 pkg 에서 계산.
- 대상: 단말 하나 또는 법정동(말단) 그룹. 시·구 일괄은 막는다. 그룹이어도 단말마다 개별 topic.
- 동시 10대, 10~16시. 한 대의 끝 = `DONE`·`ROLLBACK`·오류 OTA_ACK.
- 버전 확인: 당분간 `DONE` 으로 성공 판정(단말 fw 1.4.0 고정), 버전 관리가 시작되면 비교를 더한다.
- 기록: 단말별 job_id·시작·결과·시각, 보낸 pkg(이름·크기·sha256).

## 24.6~24.9 요약
- 3,840 바이트씩 약 48번, 받기 약 2~3.5분 + 재부팅·재접속 약 1분, 1회 약 470KB.
- 모뎀: URL 은 `http(s)://` 를 빼고 AT 명령에 준다, 바이너리 불가(→ base64), 4KB 부터 빠짐(→ 3,840), 인증서 검증 끄고 SHA-256 으로 확인.
- 실기(2026-10-17): 펌웨어 138,576 B → pkg 184,768 B, 49조각, `DONE` 까지 약 4.5분. 확정 전 전원 차단 3번 → `ROLLBACK`. `sha256` 틀림 → `HASH`.
- 1차에 넣지 않는 것: 버전 비교·강제 버전 / 진행률 보고 / 서버 명령 되돌리기 / 이미지 서명·암호화.
