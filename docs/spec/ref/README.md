# 1년 스케줄 표 계산 — 서버용 기준 구현

**6차(스케줄 배포)에서 쓴다. 2·3차 작업에는 필요 없다.**

단말, PC 설정 도구, 서버가 같은 조건(좌표, 보정)으로 **비트 단위로 같은** 372일
점등/소등 표를 만들어야 한다. 그래야 서버는 표 대신 조건만 보내고(메시지 1번),
단말이 계산한 표가 맞는지 CRC 하나로 확인할 수 있다.

| 파일 | 내용 |
|---|---|
| `suntable.py` | 기준 구현. Python 3.8 이상, 외부 패키지 없음. **고치지 말고 그대로 쓴다** |
| `suntable_vectors.json` | 시험값 118건. 입력과 372칸 표의 CRC-32, 날짜 4개의 값 |

## 쓰는 법 (서버가 Python 이면)

```python
import suntable
table = suntable.build_table(lat_e6=37566500, lon_e6=126978000, on_corr=0, off_corr=0)
crc = suntable.table_crc32(table)      # 단말 응답 CRC 와 비교
```

- `lat_e6`, `lon_e6` : 도 x 1,000,000 **정수**. 서버 DB 에 이 정수로 저장하고 그대로 넘긴다.
  실수 좌표에서 바꿀 때는 `round(lat * 1e6)`
- `on_corr`, `off_corr` : 점등/소등 보정(분), -180 ~ 180
- 결과 : 372칸 `[(점등 시, 분, 소등 시, 분), ...]`, 월마다 31칸(없는 날짜는 앞날 값)
- 시간대는 KST 고정, 연도 없음(윤년 달력으로 계산해 해마다 같이 쓴다)

## 다른 언어로 옮길 때

실수(float/double)로 다시 짜면 **안 된다.** 삼각함수 마지막 자리가 달라 드물게 1분씩
어긋나고 CRC 가 달라진다. `suntable.py` 를 줄 단위로 옮기고 아래를 지킨다.

1. 64비트 정수. JavaScript 는 BigInt
2. 오른쪽 시프트, 나눗셈, 나머지는 모두 **내림(floor)**. C/Java/C#/JS 의 `/` `%` 는 0 쪽으로
   자르므로 `asr`, `fdiv`, `fmod` 같은 도우미를 만든다 (단말 `FW/Modules/suntable.c` 참고)
3. 상수(ATAN 표, KINV, K_*)는 계산하지 말고 정수 그대로 쓴다
4. `den <= 0`(극점) 이면 그날은 계산 불가로 본다. 0 으로 나누지 않는다
5. CORDIC 반복부의 값은 32비트 안에 들어간다(단말은 32비트로 돈다). 64비트로 돌려도 결과는 같다
6. `suntable_vectors.json` 118건이 **모두** CRC 까지 같아야 한다

## 검증 상태 (2026-09-26)

| 대조 | 결과 |
|---|---|
| 단말 실기(ARM Cortex-M0+) | 서울 0/0 `69C1DF86` 과 날짜 4개 **일치** |
| 단말 C 구현 vs 이 파일 | 1,118건(시험값 118 + 무작위 1,000, 위도 ±90 전체) x 372칸 전체 **완전 일치** |
| 공표 일출/일몰 (서울·부산 5건) | 2분 이내 |
| 실수 계산(NOAA 식) | 국내 108지점 x 372일 중 1분 차이 7개, 나머지 같음 |

판 : `SUNTABLE-1`. 식을 바꾸면 판을 올리고 단말·도구·서버를 함께 바꾼다.
