## 3. 이번 업무

### W-1 알람(조치 필요) 화면 — S-24 · 사양서 §16.6

| | 내용 |
|---|---|
| **[필수]** | Telemetry `er` 는 bit 묶음(§16.2.2). 0x0001 저전압, 0x0002 시각 미확보, 0x0004 LED FAULT, 0x0010 MPPT 무응답, 0x0020 기본 스케줄. 0x0008 예약, 0x0040(LTE_OFFLINE)은 알람으로 쓰지 않는다 |
| 단말 동작 (알고만 있으면 됨) | `er` 가 바뀌면 **2초 뒤 Telemetry** 가 온다. 1분 안에 또 바뀌면 모아서, **10분에 5건이 넘으면 주기(`ti`) 보고로만**. 보내기 전 원래 값으로 돌아오면 안 보낸다. 서버가 따로 과보고를 막을 필요 없다 |
| [추천] 탭 | 전체 · 고장 · 통신 두절 · 승인 대기 · 설정 불일치 · 현장 조작 |
| [추천] 항목·기준 | 고장 = `er` bit / 통신 두절 = 브로커 끊김 또는 `ti` x 2 + 5분 무수신 / 재부팅 잦음 = 하루 `sq` 감소 3회 / 승인 대기 = PENDING / 설정 불일치 = `cv` 30분 넘게 다름, Telemetry `ss` 변화, `tbl.crc` 다름 / 현장 조작 = `md:1` 1시간 넘게 |
| [추천] 공통 | ACTIVE 단말만(SUSPENDED 제외), 한 단말·한 항목 열린 알람 1건, 해제되면 이력, 다시 생기면 새 건, 등급 → 최신순 |
| 뒤로 | 문자·메일 알림 전송 |

### W-2 스케줄 배포 화면 (등록 포함) — S-25 · 사양서 §13.1

| | 내용 |
|---|---|
| **[필수]** | 메시지는 `SETTINGS_SET`(UI 명세 8.4) : `v` **25개 전부** + `tbl`(`region` `lat_e6` `lon_e6` `on` `off` `crc`). `crc` = `suntable.table_crc32(suntable.build_table(...))` **그대로**. 단말마다 `device/{uuid}/cmd`, 한 줄 JSON, `ACTIVE` 만. 단말이 같은 식으로 계산해 crc 가 같을 때만 저장하고 `OK` |
| **[필수]** | 기존 `SCHEDULE_UPDATE`·chunk 전송은 **쓰지 않는다**(단말에 없음) |
| [추천] 화면 | ① 프로필 등록(카카오 주소 → 지역·좌표, 보정, 운전 15개, 미리보기) ② 법정동 트리 배정(단말 예외 가능) ③ 배포 진행 표·응답 없는 단말만 재시도 ④ ACK·crc 로 "적용됨" ⑤ 단말 상세 스케줄 탭 |
| [추천] 절차 | 25개 = 그 단말의 **마지막 읽은 값** + 프로필 15개 덮기(현장 기준 밝기·배터리 값을 덮지 않게). 안 읽었으면 `SETTINGS_GET` 먼저. 30초 무응답이면 새 `seq` 로 3회까지. 오프라인은 다시 접속하면 자동. 초당 10대 이하 |

### W-3 운영 8883 에서 흐름 재통과 — S-22 (4차 합격 기준 3)

8883 에서 승인 흐름(PENDING → ACTIVE → SUSPENDED → ACTIVE, 거절, 폐기)과 CONFIG·원격 명령을 한 번 더 확인.
1883 에서 합격한 것을 그대로 반복하면 된다. 날짜를 정해 주면 단말을 붙인다.

## 5. 서버 의견을 받고 싶은 것

1. 알람 기준 시간(통신 두절 `ti` x 2 + 5분, 설정 불일치 30분, 현장 조작 1시간)과 등급 — 운영 경험상 다른 값이 낫다면.
2. 스케줄 프로필에 운전 15개를 같이 넣는 것 — 조건(`tbl`)만 배포하고 15개는 단말별 설정 화면에서 따로 다루는 편이 낫다면.
3. 배포 재시도(30초 · 3회)와 오프라인 단말 자동 배포 — 서버 큐 구조에 맞는 방식이 따로 있다면.
4. `SCHEDULE_UPDATE` 를 없애고 `SETTINGS_SET` 으로 통일하는 것에 문제가 없는지.
5. 그 밖에 [필수] 규격 중 서버 구현이 어려운 것.

## 6. 시험 방법

- 서버 없이 단말 한 대 : `python Tools\mqtt_test.py --device-uuid <UUID> --settings-get`,
  `--settings-set "{}" --tbl 서울,37.5665,126.978,0,0` (UI 명세 8.9)
- 가상 단말(vdev) : 우리 PC 에서 가상 단말(`FFFF…` UUID)을 서버에 붙여 문제를 자동 판정하고 **서버용 보고서**를 보내 준다.
  LED FAULT·저전압·MPPT 버튼으로 `er` 알람을, `SETTINGS_SET` 수신으로 스케줄 배포를 시험할 수 있다.
  시험 날짜를 알려 주면 돌린다. 지금 서버에 1번 가상 단말 `FFFF00000000000000000001` 이 PENDING 으로 있다(시험용).
- 실기 단말 : 보드 3대. `er` 는 LED 드라이버 fault·MPPT 선 분리로 만들 수 있다.
